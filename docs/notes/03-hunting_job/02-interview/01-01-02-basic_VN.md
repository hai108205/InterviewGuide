## 21. Sự khác biệt giữa C++ và Java

* **Đặc tính ngôn ngữ**: Java là ngôn ngữ hướng đối tượng thuần túy, chạy trên máy ảo JVM (Write Once, Run Anywhere), không có con trỏ trực tiếp. C++ biên dịch trực tiếp ra mã máy nhị phân, hỗ trợ con trỏ thao tác bộ nhớ trực tiếp và đa kế thừa (Multiple Inheritance).
* **Quản lý bộ nhớ & Thu gom rác (Garbage Collection)**: Java sử dụng cơ chế Garbage Collector (GC) tự động dọn dẹp bộ nhớ trên Heap. C++ yêu cầu lập trình viên tự quản lý thông qua Constructor/Destructor, toán tử `new`/`delete` hoặc Smart Pointers (RAII).
* **Ứng dụng**: C++ chiếm ưu thế tuyệt đối ở tầng hệ thống (Operating Systems, Game Engines, Embedded, High-performance Backend). Java thống trị mảng dịch vụ Web doanh nghiệp, Android và Big Data.

## 22. Sự khác biệt giữa struct và class trong C++

- **Phạm vi truy cập mặc định**: Thành viên và kế thừa trong `struct` mặc định là `public`. Trong `class` mặc định là `private`.
- Mọi chức năng `class` làm được thì `struct` trong C++ cũng đều làm được (kế thừa, đa hình, hàm thành viên).
- **So sánh với C struct**: `struct` trong C thuần túy chỉ là tập hợp dữ liệu (User-Defined Type), không thể chứa hàm thành viên và không có quyền truy cập `private`/`protected`.

<p id = "define宏定义和const的区别"></p>

## 23. Sự khác biệt giữa Macro (#define) và const?

- **Giai đoạn xử lý**: `#define` được xử lý ở bước tiền xử lý (Text Replacement). `const` được xử lý trong quá trình biên dịch, có kiểu dữ liệu và phạm vi (Scope).
- **An toàn kiểu (Type Safety)**: `const` được trình biên dịch kiểm tra kiểu an toàn, hỗ trợ gỡ lỗi (Debugging). Macro không kiểm tra kiểu.
- **Bộ nhớ**: Macro chèn trực tiếp làm phình to mã nhị phân. `const` có thể được tối ưu hóa trong bảng hằng (Constant Folding) và chỉ cấp phát ô nhớ khi bị lấy địa chỉ (`&`).

<p id = "西加加中的作用"></p>

## 24. Vai trò của const và static trong C++

* **Từ khóa `static`**:
  - *Ngoài Class*: Giới hạn phạm vi của biến/hàm toàn cục chỉ trong file biên dịch nội bộ (Internal Linkage), ẩn với các file khác; biến `static` cục bộ duy trì giá trị qua các lần gọi hàm (lưu ở phân đoạn `.data`/`.bss`).
  - *Trong Class*: `static` member thuộc về toàn bộ Lớp (không gắn với từng Object cụ thể); `static` member function không có con trỏ `this`, không thể truy cập thành viên phi tĩnh và không thể là hàm ảo `virtual` hay hàm hằng `const`.
* **Từ khóa `const`**:
  - *Ngoài Class*: Khai báo hằng số không thể thay đổi giá trị.
  - *Trong Class*: `const` member variable bắt buộc phải khởi tạo trong Constructor Initializer List; `const` member function cam kết không làm thay đổi trạng thái của Object (chỉ được phép sửa đổi các biến được đánh dấu `mutable`).

<p id = "西加加的顶层康思特和底层康思特"></p>

## 25. Top-level const (const cấp cao) và Low-level const (const cấp thấp)

- **Top-level const**: Bản thân con trỏ hoặc đối tượng là hằng số (nằm bên phải dấu `*`).
  ```cpp
  int* const p1 = &a; // Top-level const: p1 là hằng con trỏ
  const int c = 10;   // Top-level const: c là hằng số
  ```
- **Low-level const**: Đối tượng mà con trỏ hoặc tham chiếu trỏ tới là hằng số (nằm bên trái dấu `*`).
  ```cpp
  const int* p2 = &a; // Low-level const: *p2 không thể bị gán lại
  const int& r = a;   // Tham chiếu const luôn là Low-level const
  ```
- Khi ép kiểu bằng `const_cast<T>()`, chỉ có thể loại bỏ thuộc tính Low-level const.

## 26. Sự khác biệt giữa Tên mảng và Con trỏ trỏ tới phần tử đầu tiên?

- Tên mảng đại diện cho toàn bộ mảng (có thể hiểu như hằng con trỏ), không thể thực hiện thao tác tự tăng/giảm (`arr++` bị lỗi).
- `sizeof(arr)` trả về tổng kích thước toàn bộ mảng trong bộ nhớ.
- Khi truyền mảng vào tham số hàm, tên mảng tự động thoái hóa (Decay) thành con trỏ thông thường (`int*`), khi này `sizeof` chỉ trả về kích thước con trỏ (4/8 bytes).

<p id = "final和override关键字"></p>

## 27. Từ khóa final và override trong C++11

- **`override`**: Đảm bảo hàm ở lớp con bắt buộc phải ghi đè (override) một hàm ảo có sẵn ở lớp cha. Nếu sai tên hàm hoặc sai tham số, trình biên dịch sẽ báo lỗi ngay lập tức.
- **`final`**:
  - Đặt sau tên lớp để ngăn chặn lớp khác kế thừa (`class A final : Base {};`).
  - Đặt sau hàm ảo để ngăn chặn các lớp con tiếp tục ghi đè hàm này (`virtual void foo() final;`).

<p id = "拷贝初始化和直接初始化"></p>

## 28. Khởi tạo sao chép (Copy Initialization) và Khởi tạo trực tiếp (Direct Initialization)

- **Direct Initialization (`string s("abc");`)**: Gọi trực tiếp Constructor phù hợp nhất với danh sách tham số.
- **Copy Initialization (`string s = "abc";`)**: Về mặt lý thuyết sẽ tạo một đối tượng tạm thời rồi gọi Copy Constructor để tạo đối tượng đích. Trình biên dịch hiện đại thường tối ưu hóa bước này (Copy Elision / RVO).

<p id = "初始化和赋值的区别"></p>

## 29. Sự khác biệt giữa Khởi tạo (Initialization) và Gán giá trị (Assignment)?

- **Khởi tạo (`A a = b;` hoặc `A a(b);`)**: Diễn ra khi đối tượng được sinh ra trong bộ nhớ, kích hoạt **Copy Constructor**.
- **Gán giá trị (`a = b;`)**: Diễn ra khi đối tượng đã tồn tại từ trước, kích hoạt toán tử gán **`operator=`**.

<p id = "欸克斯西的用法"></p>

## 30. Cách sử dụng extern "C"

Trong C++, trình biên dịch áp dụng cơ chế Name Mangling (đổi tên hàm theo kiểu tham số để hỗ trợ nạp chồng). `extern "C"` thông báo cho trình biên dịch xử lý khối mã theo quy ước đặt tên và liên kết chuẩn của ngôn ngữ C.

```cpp
#ifdef __cplusplus
extern "C" {
#endif

// Khai báo các hàm C thuần túy
int add(int a, int b);

#ifdef __cplusplus
}
#endif
```

<p id = "野指针和悬空指针"></p>

## 31. Con trỏ hoang (Wild Pointer) và Con trỏ lơ lửng (Dangling Pointer)

- **Wild Pointer (Con trỏ hoang)**: Con trỏ chưa từng được khởi tạo, trỏ vào một địa chỉ rác ngẫu nhiên.
  - *Giải pháp*: Luôn khởi tạo con trỏ bằng `nullptr` ngay khi khai báo.
- **Dangling Pointer (Con trỏ lơ lửng)**: Con trỏ trỏ tới vùng nhớ đã bị giải phóng (`free`/`delete`).
  - *Giải pháp*: Sau khi `delete ptr;`, lập tức gán `ptr = nullptr;` hoặc sử dụng Smart Pointers (`std::unique_ptr`, `std::shared_ptr`).

<p id = "西河西加加的类型安全"></p>

## 32. An toàn kiểu (Type Safety) trong C và C++

- C không an toàn kiểu: Cho phép ép kiểu `void*` tùy tiện, hàm `printf` nhận sai format specifier dẫn đến lỗi Crash bộ nhớ.
- C++ cung cấp các cơ chế an toàn kiểu vượt trội:
  - `template` thay thế cho hàm nhận `void*`.
  - Toán tử `new` trả về con trỏ đúng kiểu.
  - Bộ 4 toán tử ép kiểu chuẩn: `static_cast`, `dynamic_cast` (kiểm tra RTTI an toàn khi downcasting), `const_cast`, `reinterpret_cast`.

## 33. Phân biệt Nạp chồng (Overload), Ghi đè (Override) và Ẩn hàm (Hiding / Name Masking)

| Tiêu chí | Overload (Nạp chồng) | Override (Ghi đè) | Hiding (Ẩn hàm) |
| :--- | :--- | :--- | :--- |
| **Phạm vi** | Cùng trong 1 lớp (Scope) | Giữa Lớp cha và Lớp con | Giữa Lớp cha và Lớp con |
| **Tên hàm** | Giống nhau | Giống nhau | Giống nhau |
| **Tham số** | Bắt buộc phải khác nhau | Bắt buộc phải giống hệt nhau | Có thể giống hoặc khác nhau |
| **Từ khóa virtual**| Không bắt buộc | Hàm lớp cha **bắt buộc phải là `virtual`** | Hàm lớp cha không phải là `virtual` (hoặc khác tham số) |

## 34. Các loại Constructor trong C++

1. **Default Constructor (Hàm khởi tạo mặc định)**: Không có tham số hoặc tất cả tham số đều có giá trị mặc định.
2. **Parameterized Constructor (Khởi tạo có tham số)**.
3. **Copy Constructor (Khởi tạo sao chép)**: Nhận tham số `const ClassName&`.
4. **Move Constructor (Khởi tạo di chuyển - C++11)**: Nhận tham số rvalue reference `ClassName&&`.
5. **Delegating Constructor (Khởi tạo ủy quyền - C++11)**: Constructor này gọi một Constructor khác cùng lớp.
6. **Conversion Constructor (Khởi tạo chuyển đổi)**: Nhận 1 tham số duy nhất để chuyển đổi kiểu ngầm định (trừ khi có từ khóa `explicit`).

<p id = "浅拷贝和深拷贝的区别"></p>

## 35. Phân biệt Sao chép nông (Shallow Copy) và Sao chép sâu (Deep Copy)

- **Shallow Copy (Sao chép nông)**: Chỉ sao chép từng bit giá trị của các trường. Nếu lớp chứa con trỏ trỏ tới vùng nhớ Heap, cả 2 đối tượng sẽ cùng trỏ tới một ô nhớ, dẫn đến lỗi **Double Free Crash** khi đối tượng bị hủy.
- **Deep Copy (Sao chép sâu)**: Cấp phát một vùng nhớ Heap mới hoàn toàn độc lập và sao chép nội dung thực tế sang vùng nhớ mới đó.

<p id = "内联函数和宏定义的区别"></p>

## 36. Sự khác biệt giữa Hàm nội tuyến (inline) và Macro (#define)?

- `inline` được trình biên dịch xử lý tại bước Compile, có kiểm tra kiểu dữ liệu an toàn, hỗ trợ nạp chồng và gỡ lỗi.
- Macro chỉ là cơ chế thay thế chuỗi trước biên dịch, dễ gây tác dụng phụ do thứ tự ưu tiên toán tử nếu thiếu dấu ngoặc đơn `()`.

<p id = "怕布雷克访问和继承权限怕布雷克噗若外套的区别"></p>

## 37. Quyền truy cập và Kế thừa: public, protected, private

- **Phạm vi truy cập**:
  - `public`: Truy cập tự do từ bên trong và bên ngoài lớp.
  - `protected`: Chỉ có thể truy cập từ bên trong lớp đó và các lớp dẫn xuất (lớp con).
  - `private`: Chỉ có thể truy cập duy nhất từ bên trong chính lớp đó.
- **Quy tắc kế thừa**:
  - Kế thừa `public`: Giữ nguyên thuộc tính `public` và `protected` của lớp cha.
  - Kế thừa `protected`: Các thành viên `public` của lớp cha trở thành `protected` trong lớp con.
  - Kế thừa `private`: Mọi thành viên của lớp cha trở thành `private` trong lớp con.
  - Thành viên `private` của lớp cha luôn bị ẩn và không thể truy cập trực tiếp từ lớp con ở mọi chế độ kế thừa.

<p id = "如何用代码判断大小端存储"></p>

## 38. Cách viết mã kiểm tra kiến trúc Big-Endian hay Little-Endian?

- **Big-Endian**: Byte có trọng số cao nhất (MSB) lưu ở địa chỉ bộ nhớ thấp nhất.
- **Little-Endian**: Byte có trọng số thấp nhất (LSB) lưu ở địa chỉ bộ nhớ thấp nhất (hầu hết CPU x86/ARM tiêu chuẩn).

```cpp
#include <iostream>
int main() {
    int a = 0x1234;
    char c = (char)a;
    if (c == 0x34) {
        std::cout << "Little Endian" << std::endl;
    } else if (c == 0x12) {
        std::cout << "Big Endian" << std::endl;
    }
    return 0;
}
```

## 39. Cách dùng các từ khóa volatile, mutable và explicit

- **`volatile`**: Báo cho trình biên dịch biết biến có thể bị thay đổi bất ngờ bởi phần cứng hoặc luồng khác, vô hiệu hóa việc tối ưu lưu biến vào thanh ghi CPU (Register), luôn đọc trực tiếp từ RAM.
- **`mutable`**: Cho phép một biến thành viên có thể được chỉnh sửa giá trị ngay cả bên trong hàm thành viên hằng (`const member function`).
- **`explicit`**: Đặt trước Constructor có 1 tham số để ngăn chặn trình biên dịch thực hiện ép kiểu ngầm định (Implicit Type Conversion).

## 40. Các trường hợp kích hoạt Copy Constructor?

1. Khởi tạo đối tượng mới bằng một đối tượng cùng kiểu đã tồn tại (`A a2 = a1;` hoặc `A a2(a1);`).
2. Truyền tham số đối tượng vào hàm theo hình thức truyền giá trị (Pass-by-Value: `void func(A a)`).
3. Hàm trả về đối tượng theo hình thức trả về giá trị (Pass-by-Value return: `A func()`), trừ khi được trình biên dịch tối ưu hóa RVO/NRV.
