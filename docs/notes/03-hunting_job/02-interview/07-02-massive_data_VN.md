## 6. Thống kê Top 10 Từ khóa Tìm kiếm (Query) Hot nhất từ 10 triệu Log (RAM $\le 1\text{GB}$)

- **Đề bài**: 10 triệu query log (sau khi lọc trùng còn $\le 3\text{ triệu}$ query duy nhất), độ dài mỗi query $\le 255\text{B}$. Tìm Top 10 query xuất hiện nhiều nhất với bộ nhớ RAM $< 1\text{GB}$.
- **Giải pháp HashMap + Min-Heap (Tối ưu nhất)**:
  1. Dung lượng lưu trữ 3 triệu query duy nhất trong `HashMap`: $3.000.000 \times (255\text{B} + 4\text{B}) \approx 777\text{MB} < 1\text{GB}$ $\implies$ **Vừa vặn nạp trọn vẹn vào RAM**.
  2. Duyệt 10 triệu log, tăng biến đếm tần suất trong `HashMap<String, Integer>`: Tốn $O(N)$ thời gian.
  3. Xây dựng một **Min-Heap kích thước 10**: Duyệt qua các Entry của HashMap để tìm Top 10: Tốn $O(N \log 10)$.

## 7. Đếm số lượng Số điện thoại khác nhau (8 chữ số)

- **Giải pháp BitMap**:
  - Số điện thoại 8 chữ số có không gian từ $00000000$ đến $99999999$ ($\approx 10^8$ số).
  - Khởi tạo mảng BitMap độ dài $10^8$ bits: Dung lượng chỉ tốn $\frac{10^8}{8 \times 1024 \times 1024} \approx \mathbf{12\text{MB}}$ RAM.
  - Quét danh bạ, gán `bits[phone] = 1`. Cuối cùng đếm số lượng bit mang giá trị 1 chính là số lượng số điện thoại duy nhất.

## 8. Tìm Trung vị (Median) trong 500 triệu Số thực (RAM giới hạn)

### Cách 1: Phân đoạn Nhị phân theo Bit (Chia để trị trên Đĩa)
1. Đọc 500 triệu số, xét Bit dấu / Bit cao nhất để chia thành 2 file $f_0$ và $f_1$.
2. Đếm số lượng phần tử ở từng file để xác định xem vị trí thứ 250 triệu nằm ở file nào.
3. Tiếp tục đệ quy chia nhỏ file chứa trung vị theo các bit tiếp theo cho đến khi dung lượng file con $< \text{RAM limit}$, sau đó nạp vào RAM và áp dụng QuickSelect tìm trung vị.

### Cách 2: Dòng dữ liệu trực tuyến (Data Stream) bằng 2 Đống Max-Heap & Min-Heap
```java
class MedianFinder {
    private PriorityQueue<Integer> maxHeap = new PriorityQueue<>(Comparator.reverseOrder());
    private PriorityQueue<Integer> minHeap = new PriorityQueue<>();

    public void addNum(int num) {
        if (maxHeap.isEmpty() || maxHeap.peek() > num) {
            maxHeap.offer(num);
        } else {
            minHeap.offer(num);
        }
        // Cân bằng kích thước 2 đống (chênh lệch tối đa 1 phần tử)
        if (maxHeap.size() - minHeap.size() > 1) {
            minHeap.offer(maxHeap.poll());
        } else if (minHeap.size() - maxHeap.size() > 1) {
            maxHeap.offer(minHeap.poll());
        }
    }

    public double findMedian() {
        if (maxHeap.size() == minHeap.size()) {
            return (maxHeap.peek() + minHeap.peek()) * 0.5;
        }
        return maxHeap.size() > minHeap.size() ? maxHeap.peek() : minHeap.peek();
    }
}
```

## 9. Sắp xếp 10 File Query (Mỗi file 1GB) theo Tần suất Xuất hiện

- **Giải pháp**:
  1. Quét đồng thời 10 file, băm từng query vào 10 file con nhỏ hơn qua $\text{Hash}(query) \pmod{10}$.
  2. Nạp từng file con vào RAM, dùng `HashMap` thống kê tần suất và sắp xếp nội bộ.
  3. Áp dụng thuật toán **Sắp xếp Trộn ngoài (External Merge Sort)** để hợp nhất kết quả từ 10 file con thành file kết quả cuối cùng.

## 10. Tìm Top 500 Số lớn nhất từ 20 Mảng đã được Sắp xếp (Mỗi mảng 500 phần tử)

- **Giải pháp K-Way Merge bằng Max-Heap (Đống lớn)**:
  1. Khởi tạo một Max-Heap có kích thước đúng bằng số mảng ($K=20$).
  2. Lấy phần tử đầu tiên (lớn nhất) của mỗi mảng cùng với thông tin chỉ số mảng `source` và vị trí `index` đẩy vào Heap.
  3. Lặp 500 lần:
     - Lấy phần tử lớn nhất ra khỏi Heap (`poll()`), lưu vào mảng kết quả `Top500`.
     - Lấy phần tử kế tiếp từ mảng nguồn vừa được lấy ra, đẩy vào Heap.
  4. Độ phức tạp thời gian: $O(500 \times \log 20)$ $\implies$ **Cực kỳ nhanh và tối ưu bộ nhớ**.
