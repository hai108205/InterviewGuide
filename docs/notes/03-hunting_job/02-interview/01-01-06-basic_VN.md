## 101. Cấu trúc bộ nhớ của các tham số khi thực thi hàm main(int argc, char *argv[])

- `argc` (Argument Count): Số nguyên lưu số lượng tham số dòng lệnh truyền vào (tối thiểu là 1).
- `argv` (Argument Vector): Mảng các con trỏ `char*`, mỗi con trỏ trỏ tới một chuỗi ký tự kết thúc bằng `'\0'` nằm trong vùng nhớ Stack hoặc Environment Block của tiến trình. `argv[0]` luôn lưu đường dẫn/tên của chính file thực thi.

<p id = "volatile关键字的作用"></p>

## 102. Vai trò thực tế của từ khóa volatile trong hệ thống

- Báo hiệu cho Trình biên dịch không được tối ưu hóa việc lưu biến vào thanh ghi CPU (Register Caching), mọi thao tác đọc/ghi bắt buộc phải truy cập trực tiếp vào ô nhớ RAM thực tế.
- **3 Trường hợp bắt buộc dùng `volatile`**:
  1. Biến cờ hiệu ngắt được chỉnh sửa bên trong Trình phục vụ ngắt (ISR - Interrupt Service Routine).
  2. Biến cờ hiệu chia sẻ giữa các tác vụ (Tasks/Threads) trong hệ điều hành đa nhiệm / nhúng.
  3. Thanh ghi phần cứng ánh xạ bộ nhớ (Memory-Mapped I/O Registers).

<p id = "如果有一个空类它会默认添加哪些函数"></p>

## 103. Một Class rỗng (Empty Class) trong C++ mặc định được sinh ra những hàm nào?

Trình biên dịch C++ sẽ tự động sinh ra 6 hàm thành viên công khai mặc định (nếu có lời gọi đến):
1. Default Constructor: `Empty();`
2. Copy Constructor: `Empty(const Empty&);`
3. Destructor: `~Empty();`
4. Copy Assignment Operator: `Empty& operator=(const Empty&);`
5. Move Constructor (C++11): `Empty(Empty&&);`
6. Move Assignment Operator (C++11): `Empty& operator=(Empty&&);`

<p id = "西加加中标准库是什么"></p>

## 104. Thư viện chuẩn C++ Standard Library bao gồm những thành phần nào?

1. **C Standard Library kế thừa**: Xử lý chuỗi C, toán học `<cmath>`, thời gian `<ctime>`, I/O C `<cstdio>`.
2. **Thư viện Hướng đối tượng**: Luồng I/O `<iostream>`, `<fstream>`, `<sstream>`, Xử lý chuỗi `std::string`.
3. **Thư viện Mẫu chuẩn STL (Standard Template Library)**:
   - *Containers (Thùng chứa)*: vector, list, deque, map, set, unordered_map, v.v.
   - *Algorithms (Thuật toán)*: sort, find, binary_search, transform, v.v.
   - *Iterators (Bộ lặp)*.
   - *Functors (Đối tượng hàm)*.
   - *Allocators (Bộ cấp phát)*.
4. **Hỗ trợ Đa luồng (C++11 Threading Support)**: thread, mutex, condition_variable, future/promise, atomic.

## 105. Mối quan hệ và cách chuyển đổi giữa std::string, const char* và char*

```cpp
// 1. string -> const char*
std::string s = "abc";
const char* c_s = s.c_str(); // hoặc s.data()

// 2. const char* -> string
const char* c_s = "abc";
std::string s(c_s);

// 3. string -> char* (Cần cấp phát bộ nhớ mới)
char* p = new char[s.length() + 1];
strcpy(p, s.c_str());

// 4. char* -> const char*
char* p = "abc";
const char* cp = p;
```

## 106. Nguyên tắc lựa chọn giữa Con trỏ và Tham chiếu khi truyền tham số hàm:

- **Dùng Tham chiếu hằng (`const Type&`)**: Khi truyền các Class Object hoặc Struct kích thước lớn mà không muốn hàm sửa đổi dữ liệu (chuẩn mực C++ giúp tối ưu hiệu năng).
- **Dùng Tham chiếu (`Type&`)**: Khi hàm cần sửa đổi trực tiếp dữ liệu của biến gốc truyền vào.
- **Dùng Con trỏ (`Type*`)**: Khi tham số có thể mang giá trị "không tồn tại" (`nullptr`), hoặc khi thao tác với mảng/bộ đệm C thô.

<p id = "你知道静态绑定和动态绑定吗"></p>

## 107. Phân biệt Liên kết tĩnh (Static Binding) và Liên kết động (Dynamic Binding)

- **Static Binding**: Ghép nối hàm tại thời điểm biên dịch dựa trên kiểu tĩnh đã khai báo. Áp dụng cho các hàm thông thường, hàm tĩnh, toán tử nạp chồng.
- **Dynamic Binding**: Ghép nối địa chỉ hàm tại thời điểm chạy (Runtime) thông qua Bảng hàm ảo `vtable`, áp dụng cho hàm ảo `virtual` khi gọi qua con trỏ hoặc tham chiếu lớp cha.

<p id = "如何设计一个类计算子类的个数"></p>

## 108. Cách thiết kế Class đếm số lượng đối tượng đang tồn tại trong bộ nhớ:

1. Khai báo biến tĩnh `static int count;` trong Class và khởi tạo `int ClassName::count = 0;` ở ngoài file `.cpp`.
2. Tăng `count++` trong Default Constructor, Parameterized Constructor và Copy Constructor.
3. Giảm `count--` trong Destructor.
4. Cung cấp hàm tĩnh `static int getCount() { return count; }` để truy xuất an toàn.

## 109. Cách định vị nhanh lỗi biên dịch Template phức tạp

- Lỗi Template thường sinh ra một chuỗi thông báo lỗi dài dòng (Template Instantiation Stack).
- Hãy cuộn xuống **vị trí dòng code đầu tiên thuộc về mã nguồn do chính bạn viết** (nơi khởi tạo template), thay vì nhìn vào các dòng code bên trong header thư viện STL.

**Thứ tự khởi tạo các thành viên hoàn toàn phụ thuộc vào THỨ TỰ KHAI BÁO CỦA CHÚNG TRONG CLASS**, tuyệt đối không phụ thuộc vào thứ tự bạn viết trong danh sách khởi tạo Initializer List.

## 111. Những điều cấm kỵ khi trả về Tham chiếu (Return by Reference) từ hàm:

1. **Tuyệt đối không trả về tham chiếu của Biến cục bộ (Local Variable)**: Biến cục bộ trên Stack bị hủy ngay khi thoát hàm, tham chiếu trả về trở thành tham chiếu rác (Dangling Reference) gây Crash bộ nhớ.
2. **Tuyệt đối không trả về tham chiếu của bộ nhớ cấp phát bằng `new` trong hàm**: Người gọi hàm rất dễ bỏ quên việc giải phóng bộ nhớ, gây rò rỉ bộ nhớ nghiêm trọng (Memory Leak).

## 112. So sánh strcpy, sprintf và memcpy

| Tiêu chí | strcpy | sprintf | memcpy |
| :--- | :--- | :--- | :--- |
| **Đối tượng** | Chuỗi ký tự kết thúc bằng `'\0'` | Định dạng nhiều kiểu dữ liệu ra chuỗi | Mọi khối byte bộ nhớ thô nhị phân |
| **Tốc độ** | Trung bình | Chậm nhất (phải parse format) | **Nhanh nhất** (tối ưu phần cứng SIMD) |
| **An toàn** | Dễ tràn bộ đệm nếu thiếu kiểm tra | Tiềm ẩn lỗi tràn chuỗi | An toàn theo kích thước `n` bytes |

## 113. Lợi ích khi sử dụng Tham chiếu làm tham số hàm

1. Loại bỏ hoàn toàn chi phí sao chép đối tượng và gọi Copy Constructor.
2. Cú pháp gọi hàm tự nhiên như truyền giá trị (`func(obj)`), không cần dấu lấy địa chỉ `&` như con trỏ.
3. Không lo bị truyền nhầm con trỏ rỗng `nullptr`.

<p id = "你知道数组和指针的区别吗"></p>

## 114. Phân biệt sâu giữa Mảng và Con trỏ trong C++

- Mảng là khối bộ nhớ liên tục có kích thước cố định xác định tại Compile-time (`sizeof(arr)` ra tổng dung lượng mảng).
- Con trỏ chỉ lưu địa chỉ ô nhớ (`sizeof(ptr)` luôn ra 4 hoặc 8 bytes).
- Tên mảng là một hằng địa chỉ, không thể gán lại hay tự tăng giảm (`arr++` là bất hợp pháp). Con trỏ là biến địa chỉ động, có thể thay đổi tùy ý.

<p id = "如何阻止一个类被实例化"></p>

## 115. Các phương pháp ngăn chặn một Class bị khởi tạo (Instantiate) đối tượng:

1. Đặt Constructor ở phạm vi `private` hoặc `protected` (chỉ cho phép hàm `static` hoặc lớp con khởi tạo).
2. Khai báo ít nhất một **Hàm ảo thuần túy (Pure Virtual Function: `virtual void foo() = 0;`)** để biến lớp thành **Lớp cơ sở trừu tượng (Abstract Base Class)**.
3. Trong C++11: Sử dụng `= delete` cho Constructor.

<p id = "如何禁止程序自动生成拷贝构造函数"></p>

## 116. Cách vô hiệu hóa Copy Constructor và Copy Assignment Operator

- **Cách chuẩn C++11 (Khuyên dùng)**:
  ```cpp
  ClassName(const ClassName&) = delete;
  ClassName& operator=(const ClassName&) = delete;
  ```
- **Cách C++98 (Cũ)**: Khai báo Copy Constructor và `operator=` ở phạm vi `private` và không cài đặt thân hàm (Unimplemented). Hoặc kế thừa từ lớp `boost::noncopyable`.

<p id = "你知道的八个和瑞丽丝的区别是什么吗"></p>

## 117. Sự khác biệt giữa chế độ biên dịch Debug và Release

- **Debug**: Giữ nguyên toàn bộ thông tin gỡ lỗi (Symbol Table `.pdb`), không bật tối ưu hóa mã nguồn (O0), hỗ trợ Breakpoints và kiểm tra biến từng bước. Kích thước file nhị phân lớn, tốc độ chạy chậm.
- **Release**: Bật tối ưu hóa mã nguồn mức cao (O2/O3: Inlining, Loop Unrolling, Vectorization), loại bỏ biểu tượng debug, kích thước nhỏ gọn, tốc độ thực thi tối đa.

<p id = "main函数的返回值有什么值得考究之处吗"></p>

## 118. Ý nghĩa giá trị trả về của hàm main()

Hàm `main()` bắt buộc phải trả về kiểu `int`. Giá trị trả về này (Exit Code) được gửi lại cho Hệ điều hành / Shell tiến trình cha:
- `return 0;`: Báo hiệu chương trình kết thúc thành công mỹ mãn.
- `return non-zero;`: Báo hiệu chương trình gặp mã lỗi bất thường (Error Code).

<p id = "写一个比较大小的模板函数"></p>

## 119. Cài đặt Hàm mẫu (Function Template) so sánh tìm giá trị lớn nhất:

```cpp
template <typename T>
const T& Max(const T& a, const T& b) {
    return (a > b) ? a : b;
}
```
*Lưu ý*: Kiểu `T` truyền vào bắt buộc phải hỗ trợ nạp chồng toán tử so sánh `operator>`.

<p id = "strcpy函数和strncpy函数的区别"></p>

## 120. So sánh strcpy và strncpy - Hàm nào an toàn hơn?

- **`strncpy(dest, src, n)` an toàn hơn `strcpy`** vì giới hạn số lượng ký tự sao chép tối đa là `n`, tránh lỗi tràn bộ đệm (Buffer Overflow).
- *Lưu ý quan trọng*: Nếu độ dài chuỗi nguồn $\ge n$, `strncpy` sẽ **không tự động chèn ký tự kết thúc `'\0'` vào cuối chuỗi đích**. Do đó người lập trình phải luôn chủ động gán `dest[n - 1] = '\0';`.
