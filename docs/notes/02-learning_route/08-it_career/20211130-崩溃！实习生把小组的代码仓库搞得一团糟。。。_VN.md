---

### Quy trình phân nhánh Git chuẩn trong phát triển nhóm doanh nghiệp (Git Workflow):

![Quy trình phát triển Git trong doanh nghiệp](http://oss.interviewguide.cn/img/202205121654308.png)

1. **Nhánh Tính năng (`feat/XXX`)**: Mỗi lập trình viên tạo nhánh riêng tách ra từ nhánh phát triển chung `dev` để thực hiện nhiệm vụ được giao.
2. **Hợp nhất vào `dev`**: Sau khi hoàn thành và tự kiểm thử (Unit Test), gửi Pull Request / Merge Request vào nhánh `dev` và giải quyết xung đột (nếu có).
3. **Chuyển sang nhánh Kiểm thử (`test/staging`)**: Chuyển giao code cho đội ngũ QA/QC kiểm thử tự động và thủ công.
4. **Hợp nhất vào nhánh Phát hành (`master/main/release`)**: Sau khi vượt qua tất cả các bài kiểm thử nghiêm ngặt, code mới được phép merge vào `master` để triển khai lên môi trường Production (CI/CD Pipeline).
